OntoAgentic / Project field guide
An experimental cognitive architecture

Many perspectives.
One agent.

OntoAgentic is a Python framework scaffold for persistent agents whose behavior is meant to emerge from interacting cognitive Parts, a guiding Identity, and a single Self that chooses what to do.

01 / How cognition is intended to work

The canonical agent cycle

This is the architecture the scaffolding is organized around. It describes intended responsibilities, not a finished executable pipeline.

The environment supplies facts. Parts give them meaning. Self makes the choice.

03 · perspectivesPartsInterpret, react, forecast, and sometimes bid
04 · integrationSelf + IdentitySelf selects; Identity guides the choice

02 / The main boundaries

What the scaffold makes room for

Folders and README files establish ownership seams so implementations can evolve without collapsing cognition into a model call or a simulation.

◉

Parts

Persistent, bounded perspectives with missions, bias, subjective memory, relationships, predictions, and a developmental history. The Part Manager owns population and lifecycle, not arbitration.

⌁

Activation & bidding

Retrieval narrows candidates; independent bounded judgments decide who activates. Activated Parts may offer context without bidding, or make proposals for Self.

◇

Self & Identity

Identity is persistent self-definition. Self is temporary, bounded integration: it chooses among available proposals, or requests a world-blind debate.

↗

Runtime & inference

Deterministic runtime controls workflow. Decision inference handles bounded judgments; generative reasoning handles open-ended Part cognition and debate. Providers remain replaceable.

▧

World & simulation

Simulation owns authoritative external truth and validates attempted actions. Agents own interpretation and psychological meaning. Simulation connects through narrow interfaces.

⌕

Memory, history & inspection

Subjective memories belong to Parts. Storage is separate from domain history. Inspection is intended to make important decisions and development observable.

05 / Deliberately unsettled

Questions left open for experiments

The architecture protects boundaries while leaving many mechanisms configurable. These decisions should follow evidence rather than folder names.

How should Parts be represented, formed, split, merged, and eventually archived?
What should subjective memory, forgetting, retrieval, and consolidation look like?
How do bids connect to Self arbitration and executive machinery?
Which inference, indexing, caching, and concurrency choices fit real workloads?
What simulation authoring format and external engine integrations are useful?
How should prediction evidence influence development while preserving each Part’s perspective?
06 / Guardrails

Rules that shape future code

These are the most useful mental checks when reading or extending this scaffold.

Meaning stays plural

Parts can disagree, hold bias, and preserve subjective interpretations.

Authority stays singular

Self chooses; Executive enacts. Parts do not act directly on the world.

Truth has an owner

Simulation owns world facts; agents own beliefs and psychological meaning.

Mechanics stay replaceable

Provider, model, storage, and simulation choices do not define cognitive identity.
