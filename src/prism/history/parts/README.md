# Part History

Part History records persistent developmental versions of Parts.

It should eventually support:

- version ancestry;
- mutation provenance;
- comparison;
- rollback;
- branching;
- split ancestry;
- merge ancestry;
- archival history;
- reactivation history.

History does not decide what a Part should become. It records what happened to it.

Current Part state belongs to the Parts system. Historical relationships belong here.
