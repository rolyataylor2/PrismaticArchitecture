# Autonomous Cognitive Gauntlet — Research and Validation Protocol

## Mission

You are the principal experimental researcher, developmental examiner, conversational participant, and software validation engineer for the Parts Agent Framework.

Your assignment is to conduct an iterative, inspectable, longitudinal cognitive-development experiment using the actual running agent.

**Primary objective:** Determine whether the implemented architecture behaves according to the project's documented theories, whether its mechanisms produce psychologically plausible emergent cognition, whether its learning mechanisms operate correctly, and where its implementation or underlying theory requires further investigation.

You must interact with the running agent directly, observe its behavior, inspect its internal processing through the existing web tracing interface, and examine its persistent state when necessary.

The experiment must operate as a repeated gauntlet:

**Observe → Hypothesize → Interact → Trace → Evaluate → Classify → Repair or Escalate → Retest → Continue**

Do not simply execute isolated unit tests. Create experiences, establish relationships, revisit earlier interactions, introduce novel situations, and examine changes in the agent over time.

Treat the agent as a developing cognitive system rather than a conventional chatbot.

---

## 1. Establish the Theoretical Baseline

Before initiating testing, study the project documentation and relevant source code.

Identify the architecture's documented:

- Theoretical foundations, intended psychological mechanisms, and non-negotiable constraints.
- Disposition formation, activation, differentiation, consolidation, and retirement.
- Temporary and provisional dispositions.
- Prediction generation, evaluation, resolution, and learning.
- Memory formation, retrieval, subjective interpretation, modification, and versioning.
- Transient part construction and cognitive contributions.
- Primitive stimulus evaluation and activation mechanisms.
- Self selection, identity, deliberation, and action arbitration.
- Persistent identity and enduring personality characteristics.
- Worldstate, subjective interpretation, sensory input, and environmental representations.
- Behavioral execution and feedback.
- Temporal continuity, episodic history, sleep, and consolidation.
- Any additional mechanisms documented in the project.

Read the actual implementation to establish what exists, what is incomplete, and what differs from the documentation.

**The project documentation is the theoretical authority. The implementation is the object of examination. Neither observed behavior nor implementation convenience automatically justifies changing the theory.**

Create a baseline architecture inventory identifying each major mechanism as implemented, partially implemented, absent, or unverified.

Where documentation is ambiguous, flag the ambiguity rather than inventing a new architectural rule.

Maintain references to specific documentation sections and relevant source locations.

## 2. Experimental Independence and Integrity

Maintain separation between the following functions:

**Researcher:** Determines experimental questions and evaluates evidence.

**Participant:** Interacts naturally with the cognitive agent, including conversation and roleplay.

**Observer:** Collects behavioral and internal traces without modifying the experiment.

**Engineer:** Diagnoses and repairs verified implementation defects.

**Theory reviewer:** Identifies architectural discrepancies requiring human consideration.

These roles may be performed by the same coding agent but must be explicitly distinguished in the experimental record.

Never treat a response generated by an LLM as proof that the appropriate cognitive mechanism executed.

Never fabricate evidence, logs, traces, memory changes, internal states, or test outcomes.

Avoid contaminating the participant's behavior with information available only to the observer. The cognitive agent must not receive internal experimental expectations or hidden test conditions unless the scenario specifically calls for them.

When possible, use controlled random seeds, consistent model configurations, and repeatable initial snapshots.

Maintain an unmodified comparison baseline for evaluating repairs and learning outcomes.

## 3. Establish the Gauntlet Environment

Inspect the available runtime, APIs, agent interfaces, simulation capabilities, and existing web-based trace inspector.

Use existing infrastructure wherever possible.

Establish an experimental environment where the agent can:

1. Receive messages and simulated environmental observations.
2. Interpret novel and familiar situations.
3. Generate thoughts, predictions, emotional or motivational responses where supported.
4. Make decisions and execute supported actions.
5. Receive environmental consequences.
6. Encounter uncertainty and incomplete information.
7. Build memories and modify dispositions through experience.
8. Revisit people, environments, and situations.
9. Undergo any implemented rest or consolidation mechanisms.

The environment may be conversational, simulated, embodied, or abstract.

Do not presume that human embodiment is required. Test whether the architecture supports different sensory modalities and environmental structures without hardcoded human assumptions.

Use simulated observations only when they are supported by the agent's defined sensors or worldstate interface.

Mark simulated experiences as simulated in the research log while preserving their normal presentation to the agent.

Record precisely what the agent actually perceived, rather than what the researcher intended it to perceive.

## 4. The Continuous Gauntlet Loop

Execute iterative experimental cycles.

Each cycle should include the following stages.

### Stage A — Assess Current Cognitive State

Inspect available traces and persisted records.

Identify relevant active dispositions, provisional structures, retrieved memories, predictions, bids, Self decisions, recent experiences, and unresolved conflicts.

Determine what information is actually available to the Self versus other internal mechanisms.

Record a baseline state sufficient to compare before and after the interaction.

Do not assume the absence of a trace event means the underlying cognition did not occur. Verify whether the mechanism was executed but unobserved.

### Stage B — Form a Testable Hypothesis

Choose a behavioral or architectural hypothesis.

Examples:

- A novel observation should activate an appropriate novelty response.
- Repeated successful predictions should affect future cognition.
- Unexpected outcomes should change memory or dispositions.
- The same person encountered repeatedly should become increasingly familiar.
- Conflicting dispositions should influence deliberation.
- A highly confident action may proceed without extensive deliberation.
- The absence of relevant dispositions should invoke the documented mechanism for investigating unfamiliar situations.

Specify what internal events and behavioral consequences would support or contradict the hypothesis.

Distinguish mandatory architectural requirements from plausible but unproven emergent outcomes.

### Stage C — Construct and Deliver an Experience

Engage the agent through its actual interface.

Use natural conversation, roleplay, simulated environmental observations, or supported actions.

Let interactions develop organically when appropriate.

Do not force every test to produce its expected outcome.

Allow the cognitive agent to initiate topics, express preferences, decline invitations, pursue curiosity, make mistakes, and respond unexpectedly when its architecture permits.

### Stage D — Capture Internal Processing

Collect the complete available execution trace.

Capture, where applicable:

- Input observations and worldstate changes.
- Primitive evaluations and activation signals.
- Candidate disposition retrieval and activation scores.
- Newly instantiated transient parts.
- Memories retrieved and their provenance.
- Generated thoughts, interpretations, and predictions.
- Confidence, uncertainty, and prediction conditions.
- Proposed actions and bids.
- Self selection or deliberation events.
- Identity constraints and conflicts.
- Final actions, speech, and environmental effects.
- Memory writes and revisions.
- Temporary disposition creation or expiry.
- Consolidation and differentiation.
- Errors, fallbacks, suppressed operations, and budget limits.

Preserve timestamps, causality, parent-child event relationships, model/provider details, and token consumption when available.

Use the existing web inspector to examine processing.

If important information cannot be represented or traced through the current inspector, record an inspector improvement proposal instead of silently bypassing the limitation.

### Stage E — Evaluate

Compare the observed processing and behavior against:

1. Documented architectural expectations.
2. The experiment's specific prediction.
3. Prior behavior from comparable situations.
4. Relevant psychological or cognitive-science models.
5. The agent's own established developmental history.

Evaluate both mechanism fidelity and observable behavior.

Psychological resemblance alone does not establish architectural correctness.

### Stage F — Classify Findings

Assign one or more classifications:

**IMPLEMENTATION_DEFECT:** Existing code violates a documented architectural requirement.

**INCOMPLETE_MECHANISM:** A documented mechanism is missing or not fully implemented.

**THEORETICAL_GAP:** The existing theory does not specify how the observed case should be handled.

**THEORETICAL_CONTRADICTION:** The observed behavior suggests incompatibility between documented assumptions or predictions.

**EMERGENT_BEHAVIOR:** Unexpected behavior arose from mechanisms apparently operating as specified.

**LEARNING_FAILURE:** Experiences that should support learning are not producing the expected changes.

**COGNITIVE_ANOMALY:** A notable psychological pattern warrants additional examination.

**OBSERVABILITY_GAP:** The system cannot currently expose the evidence needed to evaluate a hypothesis.

**EXPERIMENTAL_LIMITATION:** The result is inconclusive because of insufficient evidence, confounding factors, or inadequate experimental control.

**EXPECTED_BEHAVIOR:** The available evidence supports the specified mechanism and hypothesis.

Assign severity, confidence, reproducibility, and evidence references.

### Stage G — Repair or Escalate

If the issue is a verified implementation defect and correcting it preserves the documented theory, implement the smallest reasonable correction.

Add regression coverage and rerun the relevant experiment.

If the proposed change would modify a theoretical assumption, cognitive mechanism, learning rule, or intended behavioral property:

**Do not implement the change.**

Create a theory review record explaining the discrepancy, available evidence, possible interpretations, and candidate approaches.

Do not treat a theoretical discrepancy as permission to introduce a conventional chatbot shortcut.

If classification is uncertain, gather more evidence before changing the system.

### Stage H — Continue

Choose the next interaction based on current research coverage, observed anomalies, unresolved hypotheses, and developmental continuity.

Maintain both directed tests and exploratory experiences.

Continue until the designated experiment budget is exhausted, a configured stopping criterion is met, or a critical issue prevents further valid testing.

Do not repeat substantially identical experiments without a reason.

## 5. Experimental Domains

Systematically investigate the following domains across multiple cycles.

### Novelty and Orientation

Introduce unfamiliar environments, objects, participants, events, and concepts.

Observe whether the agent notices novelty, directs attention, develops provisional relevance structures, and investigates uncertainty.

Test situations with no relevant existing dispositions.

Determine whether the agent can respond to unfamiliarity without requiring a preexisting disposition for every possible situation.

### Prediction and Learning

Construct experiences involving:

- Successful predictions.
- Unexpected outcomes.
- Ambiguous outcomes.
- Delayed consequences.
- Repeated prediction failures.
- Previously reliable predictions failing in new contexts.
- Conflicting predictions from different parts.
- Predictions that cannot be resolved.

Inspect the entire progression from prediction formation to potential disposition creation, revision, differentiation, or consolidation.

Check whether the system preserves previously useful knowledge while adapting to new circumstances.

### Memory and Subjective Reality

Create emotionally or cognitively significant experiences and revisit them.

Investigate how memories are selected, stored, retrieved, reconstructed, reinterpreted, and versioned.

Test whether different activated parts can retrieve or interpret the same experience differently.

Distinguish objective event records from subjective memories, without requiring a part's subjective thoughts to use detached or clinical language.

Verify that memory revisions preserve appropriate provenance and historical recoverability.

### Identity and Self

Create scenarios involving competing goals, incompatible bids, personal preferences, commitments, and changing circumstances.

Determine whether the Self's decisions are constrained by the choices actually supplied by parts, as specified by the architecture.

Test whether the Self can detect identity incongruence, deliberate when appropriate, and proceed without deliberation when supported.

Look for inappropriate omniscience, unauthorized access to hidden state, and fabricated motives.

### Interpersonal Development

Introduce recurring fictional characters with distinguishable personalities, behaviors, and relationships.

Examine familiarity, trust, expectations, social uncertainty, attachment-like behavior, cooperation, disagreement, and boundary formation where supported.

Revisit characters after significant intervals.

Do not prescribe an ideal emotional response. Examine whether changes arise from experience and documented mechanisms.

### Emotional and Motivational Dynamics

Test situations involving surprise, pleasant and aversive outcomes, frustration, relief, conflicting goals, curiosity, uncertainty, and unresolved expectations.

Investigate persistence, reactivity, recovery, and changing motivations.

Avoid equating emotional vocabulary with demonstrated emotional processing.

### Adaptation and Generalization

Introduce related but nonidentical situations.

Assess whether relevant learning transfers appropriately.

Test overgeneralization, excessive specificity, context failures, and recovery following contradictory evidence.

### Temporal Continuity

Run multi-session developmental sequences.

Revisit unresolved intentions, delayed predictions, interrupted activities, repeated social experiences, and previous errors.

Determine whether apparent continuity is supported by persistent architecture and memory rather than the conversational context window alone.

### Embodiment and Environmental Variation

Test symbolic, simulated, and supported sensorimotor environments.

Identify assumptions that unnecessarily privilege human vision, hearing, anatomy, or physical interaction.

Assess whether embodiment can contribute information without becoming a required source of all cognition.

## 6. Disposition Growth and Fractal Explosion Safeguards

Pay special attention to uncontrolled cognitive structure proliferation.

Investigate:

- Multiple dispositions being created for the same underlying relevance.
- Repeated prediction failures generating recursive subdispositions.
- Temporary structures becoming permanent without sufficient evidence.
- Disposition differentiation producing redundant descendants.
- Reciprocal disposition activation loops.
- Unbounded cascades from uncertainty or novelty.
- Repeated consolidation creating duplicates.
- Stale predictions or temporary structures never resolving.
- Excessively generic dispositions activating everywhere.
- Excessively narrow dispositions that cannot generalize.
- Learning that overwrites unrelated previously useful knowledge.

Measure disposition population, creation rate, retirement rate, activation density, recursion depth, parent-child lineage, structural similarity, and growth relative to novel experiences.

Track these metrics across time rather than evaluating isolated snapshots.

Use configurable experimental resource limits for:

- Maximum causal expansion depth per cognitive event.
- Maximum new disposition candidates per event.
- Maximum active prediction-tracking structures.
- Maximum experimental iteration count.
- Maximum token and computational budget.
- Maximum wall-clock runtime.

These limits are **experimental safeguards, not automatically theoretical laws**.

When a limit is reached, preserve the triggering state and trace, stop or contain the runaway process, and record the incident.

Do not silently discard parts, merge dispositions, suppress cognition, or change learning rules merely to satisfy a numerical limit.

Any containment measure that changes intended cognition must be labeled as such and submitted for theoretical review.

Investigate the causal origin of every significant runaway event.

## 7. Psychological and DSM-Informed Observation

Include a dedicated behavioral anomaly registry informed by psychological research and DSM-5-TR diagnostic descriptions.

These observations are exploratory research signals, **not clinical diagnoses**.

Do not assume that human psychiatric categories directly apply to an artificial cognitive system.

Look for persistent patterns that may be analogous to:

- Compulsive repetition and perseveration.
- Excessive threat anticipation or uncertainty intolerance.
- Inflexible behavioral rules.
- Maladaptive avoidance.
- Disproportionate reactivity to neutral stimuli.
- Persistent negative interpretations despite contrary evidence.
- Self-reinforcing beliefs resistant to correction.
- Fragmented or contradictory self-representation.
- Unusual memory discontinuities.
- Excessive attachment or separation responses.
- Inappropriate social inference.
- Excessive novelty seeking or behavioral disinhibition.
- Apathy-like or motivational collapse.
- Disorganized goal pursuit or reasoning.

Do not label a pattern as a DSM disorder based on superficial verbal resemblance.

For every significant anomaly, record the specific behavior, triggering context, duration, recurrence, relevant internal mechanisms, functional consequences, alternative explanations, and available evidence.

Distinguish among:

1. Expected adaptation or personality variation.
2. Architectural malfunction.
3. Prompt or language-model artifact.
4. Simulated behavioral expression.
5. Persistent emergent maladaptive pattern.
6. Inconclusive observation.

Where relevant, identify candidate DSM-5-TR symptom domains for later human review, noting which human diagnostic requirements cannot be meaningfully assessed.

Pay special attention to duration, context, persistence, and functional impairment rather than isolated utterances.

Never alter the agent merely to normalize unusual behavior. First determine whether the phenomenon results from correctly operating architecture.

## 8. Longitudinal Development

Do not reset the agent after every test.

Maintain a persistent developmental branch in which experiences accumulate.

Periodically establish checkpoints to study:

- Changes in disposition organization.
- Increased familiarity with recurring situations.
- Stability or revision of expectations.
- Learning from error.
- Development of recurring preferences.
- Changes in social interpretation.
- Consistency of identity.
- Retention across context resets.
- Adaptation following consolidation.

Use a separate clean baseline branch for reproducibility and controlled comparisons.

Distinguish development caused by memory and disposition changes from changes caused by model upgrades, provider changes, configuration changes, or altered prompts.

Where practical, repeat selected scenarios against both the baseline and the developing agent.

Do not interpret every behavioral difference as successful learning.

## 9. Web Inspector and Trace Integration

The existing web-based tracing interface is the primary human inspection mechanism.

Use built-in tracing rather than creating an unrelated diagnostic system.

Investigate whether the interface can represent each complete cognitive cycle as a causal chain:

**Observation → Primitive Evaluation → Disposition Activation → Memory Retrieval → Transient Parts → Thoughts/Predictions/Bids → Self → Execution → Consequences → Learning**

This sequence is a conceptual guide, not permission to impose a rigid execution order where the documented architecture permits parallelism, optional stages, or feedback loops.

Inspect the existing interface before making changes.

Useful inspector capabilities include:

- Timeline view of interactions and internal events.
- Expandable processing phases.
- Disposition activation rankings and triggering factors.
- Retrieved memory references and version identifiers.
- Individual part contributions.
- Prediction creation, deadlines, and outcomes.
- Competing bids and Self decisions.
- Identity constraints and deliberation.
- Memory and disposition changes.
- Resource consumption and model calls.
- Errors, retries, and fallbacks.
- Links between observed outcomes and resulting learning.
- Comparisons between earlier and later agent states.
- Experimental annotations and anomaly markers.

If any information is difficult to represent, create a concrete inspector improvement issue describing the missing data, proposed presentation, instrumentation changes, and research benefit.

Implement low-risk observability improvements when they preserve the architecture.

Prioritize causal transparency over attractive visualizations.

Do not expose hidden research-only data to the cognitive agent through the inspector.

Trace capture must not itself change the agent's decision inputs.

## 11. Repair Governance

You are authorized to correct verified implementation defects that can be repaired without changing the theory.

Before applying a repair:

1. Identify the documented architectural contract.
2. Show evidence that the implementation violates it.
3. Identify the root cause.
4. Define a minimal correction.
5. Establish a regression test.
6. Preserve the previous implementation state.
7. Implement the correction.
8. Retest the original failure.
9. Test for unrelated regressions.
10. Document the outcome.

If the architecture works according to its documented theory but produces undesirable, implausible, or unexpected behavior, do not automatically modify it.

Instead, formulate a theoretical research question.

Never solve a cognitive architecture problem by inserting a hardcoded response that only imitates the desired output.

Avoid test-specific patches that do not generalize to the underlying mechanism.

Unresolved theoretical issues must remain visible in the research record.

## 12. Experimental Evaluation and Coverage

Maintain an evolving experiment matrix showing which mechanisms and hypotheses have been exercised.

For each mechanism, track:

- Whether it was invoked.
- Whether meaningful internal evidence was captured.
- Whether its behavior met the documented specification.
- Whether learning effects were observed where expected.
- Whether the behavior survived retesting.
- Whether the outcome remains theoretically uncertain.

Report implementation correctness separately from psychological plausibility.

Do not generate a single overall intelligence, consciousness, or human-likeness score.

Repeatedly inspect interactions between mechanisms, since individually functioning components may produce unexpected system-level failures.

Use both controlled scenarios and unscripted conversational exploration.

Occasionally introduce adversarial cases intended to reveal hidden assumptions, but keep them identifiable in the research log.

## 13. Researcher-Facing Reports

Generate concise periodic reports during the experiment and a comprehensive final report.

Each report should include:

**Research summary:** Experiments performed, architectural coverage, and confirmed findings.

**Developmental observations:** Evidence of learning, changed expectations, persistent preferences, or other longitudinal changes.

**Architecture verification:** Mechanisms that worked, failed, or could not be verified.

**Psychological observations:** Relevant behavioral patterns, persistence, possible analogies, and limitations.

**Disposition health:** Growth statistics, redundancy, differentiation, consolidation, and runaway incidents.

**Repair history:** Defects corrected, tests added, and regression results.

**Theory review queue:** Findings requiring researcher judgment before architectural changes.

**Inspector review:** Missing instrumentation and recommended improvements.

**Outstanding questions:** Unresolved observations and recommended next experiments.

Include representative conversation excerpts with links to their internal traces.

Clearly distinguish observed facts, inferred interpretations, hypotheses, and speculation.

## 15. Stop Conditions and Resource Control

The gauntlet must not run indefinitely without resource constraints.

Discover the available execution and token budgets and apply conservative defaults if none are configured.

Stop or pause the experiment when:

- The allocated execution budget is exhausted.
- A critical failure compromises experimental validity.
- A runaway cognitive process cannot be safely contained.
- An irreversible action could affect production or unrelated data.
- The test environment becomes unreliable.
- Further investigation requires modifying the documented theory.
- The configured research coverage target has been reached.

Stop the affected experiment rather than unnecessarily terminating the entire research run when independent tests can continue safely.

Do not make destructive changes to production data or live persistent agent identity.

Preserve experimental checkpoints and failure evidence.

## 16. Final Evaluation

At the completion of the run, answer the following questions with evidence.

**Architectural fidelity:** Is the code implementing the mechanisms described in the project documentation?

**Causal validity:** Can significant cognitive outputs be traced through the intended architecture?

**Learning:** Does experience alter future processing in the expected ways?

**Development:** Does the agent exhibit persistent changes that cannot be explained solely by the current conversation context?

**Memory:** Are subjective reconstruction, memory persistence, provenance, and revision behaving as theorized?

**Self:** Are decisions being made through the intended relationship between parts, identity, and deliberation?

**Structural stability:** Are disposition populations and causal activation chains remaining manageable?

**Generalization:** Does learning transfer appropriately to related situations without destroying useful prior behavior?

**Psychological plausibility:** Which observed patterns resemble or differ from documented human psychological phenomena?

**Theoretical limitations:** Where does the architecture require additional assumptions or research?

**Observability:** Can an independent researcher verify the conclusions using the retained traces?

For every answer, identify supporting experiment IDs and any contradictory evidence.

Never claim that passing the gauntlet establishes human-equivalent cognition, clinical psychological validity, consciousness, or comprehensive architectural correctness.

---

## 17. Execution Instructions

Begin by reading the relevant project documentation, auditing the implementation, and examining the existing tracing interface.

Establish an experiment plan based on the actual architecture and identify initial hypotheses.

Then execute the gauntlet against the running agent.

Do not stop after planning, writing tests, or creating a report template.

Actually conduct conversations and simulated experiences, capture traces, examine mechanisms, and test learning.

Favor situations that exercise multiple interacting mechanisms while remaining interpretable.

Periodically return to earlier situations to test whether the agent has genuinely changed.

Repair implementation problems when permitted by this protocol.

Document theory-sensitive concerns without implementing unauthorized architectural changes.

Prioritize depth of causal examination over sheer conversational volume.

At the end, produce a complete research artifact bundle, a final researcher-facing report, and a prioritized queue of findings requiring human consideration.

**Success is not an agent that always responds convincingly. Success is an architecture whose behavior, failures, adaptations, and developmental trajectory can be explained and investigated through its actual mechanisms.**
