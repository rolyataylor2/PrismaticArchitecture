# ADR 0153: Self-selected procedure approval

Status: Accepted, implemented bounded selected review extending ADRs 0143/0147/0152.
Date: 2026-10-09

Ordinary cognition may propose approval or rejection of a current same-Agent procedural candidate, under an explicit researcher-configured policy. Researcher-only review remains the default. Parts receive bounded public candidate manifests and expressed evidence limitations. World-blind Self receives their expressed review proposals and chooses; it receives no raw package, tool ledger, WorldState or privileged development history.

Approval is a separate, exclusive, selected operation with no tool steps, method invocation, teaching, correction or pause authority. It does not run the skill. The host requires the actual recorded selection, exact current candidate/version, thread scope, independently passed validation, current learning/review policy, exact immutable package and current grants. Conditional approval also requires each preserved branch to reference its current approved permitted member; approval cannot silently refresh versions. Stale, unsupported, foreign, unverified or unauthorized review is blocked and reported.

The host records once-only selected review lineage and a versioned decision. Cognitive approval cannot create tool permissions, change conditions/procedure, promote maturity or establish generalization. Later application requires a fresh selected invocation and current applicability/preferences/grants. Rejection likewise preserves the candidate and expressed reason in history.

Adapters, storage and gateways must independently prevent review contracts from submitting tools or fabricating approval/completion. The operational receipt and approved skill version must agree with the selected contract and decision; a Part is not a trusted security authority. Review can be declined without changing execution or psychology.

Read-only readiness checks are preparatory evidence, not cognitive approval or dispatch authority. Ordinary proposal/admission, host policy settings, durable selected receipt, runtime enactment, factory prompt/catalog changes, readable inspection and normal-pipeline Simulation Tests are all required before this feature is complete.
