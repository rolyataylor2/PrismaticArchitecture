# ADR 0159: Agent-based dream experiences

Status: Accepted, 2026-10-11. Researcher request: Dreams should use a chosen developed Agent as their starting point, discard changes to that base by default, optionally retain ordinary experienced changes, and preserve before/after evidence.

Extends ADRs 0135/0158 for an explicit dream launch mode. Existing fresh-Agent hypothesis tests and exact reruns retain their meanings. No cognitive task or prompt access boundary changes.

## Ownership and permanence

A dream starts from the chosen Agent's actual psychology and preserved history, not scenario-authored seeds. Default discard means the source remains unchanged while a separate branch experiences the scenario. The branch and its immutable history remain available for research; discard does not mean deleting evidence. Branching copies scoped current entities, their versions, experiences, cycles, audit and settings with new internal identifiers and an explicit researcher-only source mapping. It never shares writable cognitive state or another Agent's private state during cognition. External references remain opaque provenance. Credentials stay in their existing protected storage and never enter research snapshots.

Explicit keep-changes at launch instead applies ordinary experience to the chosen base Agent. It does not promote branch psychology or overwrite the source later. All ordinary changes, including changes before a failed scenario, remain permanent; the UI discloses this. The base must have no active cognition, consolidation, execution or dream at launch. Normal researcher mutations and unrelated messages are blocked while a permanent dream is active. No rollback destroys history, and no automatic psychological merge exists.

## Experiences and cognition

Dreams use the normal Agent pipeline and scenario experiences. Research labels, permanence settings and before/after inspection do not become WorldState, Identity or Self inputs. Delivery is attributed to Experience rather than announcing a simulation. The Agent may infer that an experience is unusual; runtime cannot guarantee ignorance or impose a belief that it is real.

Dream launch does not inject hypothesis-test seed dispositions. Authored scenarios remain external starting experiences; Agent cognition supplies psychological meaning. Executive apparatus scenarios are excluded, and the selected base must have Executive disconnected: dreams do not authorize real-world tool operations or change grants. Sleep steps invoke ordinary offline consolidation. Interrupted runs remain inspectable and are not replayed on restart. A recorded local host PID supplies a narrowly bounded liveness receipt. Startup marks its dream failed only when the operating system reports that host absent, recovers that dream’s unfinished cognitive/consolidation records through existing recovery interfaces and freezes partial terminal evidence. Live or unverified hosts are left alone; PID reuse remains a conservative unresolved-liveness case.

## Evidence

Persist the launch mode, source identity, identifier mapping, actual base snapshot, branch-start snapshot, terminal snapshot (including partial failure), frozen scenario and provider provenance. Before/after comparison uses these frozen snapshots, not current source state. Recurrence grouping distinguishes developed starting psychology and permanence from fresh seeded test conditions. Rerunning a dream through the old fresh-test replay endpoint is rejected because that endpoint does not reconstruct developed psychology.

Deterministic tests establish branching, source isolation, permanence, failure evidence, access boundaries and restart preservation. Configured-model results and fixture outcomes remain separately identified; neither proves human dream psychology. No forced activation, prediction or learning result constitutes hypothesis validation.
