# ADR 0147: Conditional procedural consolidation

Status: Accepted implementation target extending ADRs 0143/0144/0146.
Date: 2026-10-08

Offline external procedural consolidation can propose conditional skill variants from ended Self-selected operational episodes without requiring an explicit teaching directive. Its bounded input contains recorded selected goals/contracts, actual method operations, expressed bid/thought/review reasons, triggering observations and independently checked outcomes, including failures and continuation without interruption. It receives no private Part state, raw WorldState, Identity or psychological mutation authority. This is procedural inference outside Self, not Part consolidation or automatic goal selection. Configured reasoning proposes applicability and escalation in language; runtime validates source references, evidence and version continuity rather than inventing their meaning. Mock inference abstains.

A conditional skill contains immutable branch references to same-Agent, scope-compatible exact method versions. Each branch preserves its inferred conditions and reason; each member retains the actual source bid and ledger. No generative output can invent tool operations or confer method approval. Candidate creation and inference are separate from current application authority. Negative episodes remain in the consolidation record, not executable failed branches. Successful outcomes are temporal evidence, not proof of a correction's causal efficacy or semantic condition coverage.

Current Part cognition sees bounded public conditional branch manifests without source audit records or private state. A new selected invocation must explicitly name a branch; there is no implicit first branch, string-condition matcher or historical preference default. Host resolution requires the current active parent and referenced active member, exact immutable versions, current scope and grants, and preservation of that branch's criterion/constraint declarations. Competing instructions, stale references and incompatible current constraints request a new cognitive decision through normal blocked feedback. Conditions are cognitive applicability declarations, not runtime proof of generalization. Other branches' historical preferences never become global constraints.

Versions, variants, inferred conditions/reasons and source methods remain inspectable and restorable. Ordinary exact skills remain valid historical knowledge. An automatically discovered candidate is not an established habit: maturity, repeated-use evidence, generalization, confidence calibration and configured-model observations remain separate required work. This increment must not claim that all correction-led learning or the original Executive thread is complete.

Researcher inspection includes later recorded invocations of each method, including uses through a conditional parent that explicitly names the method as a member. These application episodes retain the selected immutable version, actual outcomes and expressed reasons independently of administrative validation. Pending, failed or unverified use must remain visible; an invocation alone does not establish success, applicability or maturity. Inspection remains read-only and supplies no additional cognitive authority.

Rejected invocation attempts are also inspectable under the requested parent method. Their recorded rejection is not a procedural failure or an accepted member resolution. Never infer a selected member from a rejected branch request.

Application evidence summaries independently check each execution against its captured selected procedure and tool ledger, including the selected conditional member. Count each execution once, independently of repeated administrative validations. Separate passed, failed, inconclusive, pending and rejected evidence. Summaries span recorded historical method versions and do not constitute calibrated confidence, transfer validation or automatic maturity promotion.
