# ADR 0135: Inspectable simulation hypothesis tests

Status: Accepted, 2026-10-04. Requested by the researcher.

Add a dedicated Simulation Tests sidebar surface, backed by a shared application-layer registry. Each definition states a sourced hypothesis, starting conditions, scripted ordinary external experiences, controls/comparisons, observable criteria and limitations. This is researcher experimentation outside cognitive authority, not a new Agent subsystem.

Each run creates a fresh constructed Agent. Fixture mode uses ordinary bundled mocks without semantic overrides and labels results as fixture evidence. Configured mode uses the selected source Agent's provider routing, activation settings and effective prompts, copied as researcher configuration; its living psychology is not copied or edited. Configured calls occur only when the user runs the test. Runs preserve provider labels, initial seed definitions, prompt versions/text, stage progress, exact predictions, scope activation, recall references, thoughts/proposals and learned dispositions. Existing experiment persistence stores tagged simulation reports; no new cognitive storage model is needed.

Experiences use the ordinary message and consolidation interfaces. Initial seeded dispositions are explicit experimental starting conditions. No test forces a prediction, outcome judgment, disposition creation or action selection. Fixed observations are authored external scenario facts, not psychological meaning or model-authored world transitions. Self remains world-blind and execution remains external.

Measured outcomes are observed, not observed or inconclusive; run execution independently completes or fails. Missing prerequisites, including no assessable prediction, make dependent measures inconclusive. Controls and comparisons expose spurious activation, unsupported learning and generalization gaps. One run or a lexical metric cannot establish psychological truth; raw evidence supports researcher review. Mock/mixed inference is never promoted to empirical validation. Future developer-thread hypotheses extend this registry, as required by AGENTS.md.
