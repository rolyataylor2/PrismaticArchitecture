# ADR 0103: Primitive fallback contributions

Status: Accepted

When activation completes successfully with zero active Parts, the learned psyche has no opinion yet. Generate independent, basic interpretations, expressed thoughts and bids from a fixed, researcher-editable primitive set. This is not a provider-error fallback and does not apply when activated Parts simply decline to bid.

Primitives are configuration, not Parts: no lifecycle, private memory, predictions, stickiness or autonomous execution. Each receives the same immutable WorldState and its own definition only. Its prompt and language-first aspects are edited under Agent Components → Primitives, outside Settings → Prompts. Defaults are Novel, Unexpected, Pleasant, Aversive, Agent caused this, Repeat this, Stop this, Look closer, Seek interaction and Uncertain. Per-item reset restores a built-in definition; custom items reset to their creation definition. Reset-all restores the ten factory definitions.

Their explicitly attributed contributions enter existing world-blind Self arbitration and debate with Identity. Primitive debate answers use the same bounded context without memory or predictions. Self receives no WorldState or primitive inference context. Executive handoff remains unchanged. Primitive identifiers occupy the legacy partId contribution field for protocol compatibility, with sourceKind=primitive; no Part record is created.

Saved primitive definitions use optimistic revisions and researcher configuration history. Inference snapshots and products are inspectable. Primitive output cannot mutate Parts, Identity or world truth. Temperament may be authored as ordinary self-definition Identity Traits; no temperament database or automatic Identity rewrite is introduced.

Outcomes return through ordinary factual experience. Existing formation remains conservative offline Part development; a zero-Part agent currently has no owning-Part consolidation traces. Automatic formation from primitive-only experiences remains an explicit future architectural question, not an invented learning loop in this change.
