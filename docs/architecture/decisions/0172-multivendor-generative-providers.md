# ADR 0172: Gemini, Qwen and OpenRouter generation

Status: Accepted, 2026-10-15.
Source: Researcher request to add Gemini, Qwen and OpenRouter after the provider connection list.

These services implement the existing generative reasoning capability. Direct Gemini and Qwen connections use distinct credentials; OpenRouter uses its own key and explicit publisher/model identifiers. Existing OpenAI/xAI model IDs remain compatible; new IDs carry a service prefix. Main, authoring, speech, offline and thought routing with independent credentials resolve through the same factory. Thought model dropdowns include every available generative provider; enabling cross-provider thought routing requires each provider’s own key. This supersedes the earlier same-provider resource-routing restriction, without sharing sessions or credentials across services. JEV classifier and Cloudflare image responsibilities remain unchanged.

Gemini and OpenRouter request JSON Schema; Qwen Flash/Plus use JSON Object mode with the exact schema supplied in instructions. Every result passes the same local decoding and domain validation. Refusal, truncation and invalid data are infrastructure failures. Requests remain stateless with existing task-scoped templates; no Self/WorldState access changes occur. OpenRouter requires parameter support and disables provider fallbacks; usage preserves reported actual model and serving provider without inferring missing values.

Available provider credentials filter all model dropdowns. The provider list is the only credential editor. Classifier lists JEV models and defaults to JEV latest once its connection is added; image generation lists added implemented image providers (currently Cloudflare). Adding a JEV connection activates its existing bounded adapter without a second key or model save. The researcher selects from an automatically loaded OpenRouter catalog filtered to structured-output, text-output, synchronous models. Selection stores exact IDs, never automatic model routers. Provider connections optionally retain an official Alibaba API base URL to support regional/workspace accounts. This is nonsecret host configuration copied with the existing configuration mechanisms. Schema 31 expands persisted model IDs and adds this connection metadata while preserving saved settings.

Prompt review: no role or task changes; current factory prompts and catalog remain appropriate. Validation uses HTTP fixtures for endpoints, key isolation, schemas, failures and usage; browser checks cover keys, selections, catalog filtering and persistence. No psychological hypothesis or live-provider success is inferred from fixtures.
