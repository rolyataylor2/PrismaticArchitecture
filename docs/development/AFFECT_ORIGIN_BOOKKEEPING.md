# Prediction origin bookkeeping under repeated Self passes

Implemented repair, 2026-10-24. This preserves ADRs 0157 and 0165: a prediction's creation-time focus determines its exposure cohort, while predictions already open at a newly selected period's entry remain baseline. Neither bookkeeping nor outcome counts assign psychological meaning.

A preserved Coupler hunger-feedback trial failed with `Baseline predictions cannot also originate in this period`. Multiple Self passes had emitted more than one `self.affect_cycle` summary for the same source cycle. The final-row writer grouped every prediction created in that cycle under the later pass's active focus. Earlier predictions were thereby relabeled as new achievements of a period whose baseline already contained them. Immutable `self.affect_prediction_origin` creation events retained the correct earlier attribution.

The final-row writer now uses recorded origin events, as the live commit writer already does. Completed-history and researcher-analysis readers use these explicit creation events when present, retaining legacy summary attribution only for predictions with no explicit origin. Filtered history cannot turn an excluded explicit origin into a legacy fallback. Repeated summaries count each completed source cycle once in period feedback. Raw summary rows, predictions, memories, focus choices and failed source cycles remain intact. The baseline/origin overlap invariant still rejects genuinely contradictory attribution; no arbitrary deletion of overlapping prediction IDs was added.

Deterministic tests cover preserved malformed summaries, legacy-only attribution, unchanged raw history, baseline separation, repeated ordinary Self passes, and creation-event attribution. A separate read-only source audit copies the actual failed database before opening it through the SDK. Prior code reproduces the failure; corrected prior/current/analysis readers return successfully. Hashes of the original database and original report remain unchanged. This audit neither resumes failed cognition nor retries a physical operation.

Three existing affect-runtime fixtures that assert disconnected execution now explicitly set `enabled: false`; their old implicit assumption disagreed with the current speech-enabled default profile. Production execution defaults are unchanged. This is test setup, not an affect policy.

No inference task, prompt, numeric calibration parameter or psychological hypothesis was introduced. No new Simulation Test claim is made: these are provenance/plumbing regressions. The fix does not establish hunger regulation, human psychology, or causal usefulness of affect. The failed trial remains an infrastructure failure, with its original result preserved.

Validation: TypeScript checking passed. The affected affect/domain/inference/proposal/history/analysis, continuous cognition, experienced-state and memory regression group passed 65/65. The final added filtered-history assertion also passed in the two origin regressions. Running the concurrent-origin test against prior committed runtime `390c784` fails on a summary origin lacking its matching creation event; the corrected runtime passes. The source audit reproduced the old baseline/origin error in both prior-focus and researcher-analysis readers, then returned successfully through corrected prior/current/analysis readers with source hashes unchanged. Raw evidence remains under the Coupler's private failed-trial directory; no historical trial is reclassified as successful.
